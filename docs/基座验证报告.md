## 五、抓出的真实缺陷（已全部回写 PRD）

### 缺陷 1：DDL 前向外键引用（阻断级）

`messages` 表外键引用 `usage_logs(id)`，但 4.2 的建表顺序把 `usage_logs` 排在 `messages` **之后**，真实执行必然报 `relation "usage_logs" does not exist`。

**这是纯语法解析查不出来的语义错误**——此前用 libpg_query 校验 52 条 SQL 全部通过，正是因为解析器只检查语法不检查对象存在性。

**修复**：把 `usage_logs` 调整为第 10 张、`messages` 为第 11 张，与 12.3 的 FK 拓扑一致。已改 PRD 源文档并重新抽取执行验证通过。

### 缺陷 2：模块级 engine / Redis 客户端绑定 event loop

pytest-asyncio 默认每个测试函数一个新 loop，模块级单例把连接绑在首个 loop 上，第二个测试起必报 `attached to a different loop` / `Event loop is closed`。**已实测复现**。

**修复**：`conftest.py` 的 autouse fixture 在每个测试后 `await engine.dispose()` 并关闭重建 Redis 客户端。生产每 worker 单 loop 不受影响。已补进 PRD 12.2。

### 缺陷 3：httpx 的 ASGITransport 会缓冲整个响应

用它测 SSE，四个事件的到达时刻全是 `0.183s`——**根本观测不到流式**，会给出"通过"的假象。**已实测复现**。

**修复**：SSE 的 smoke test 必须起真实 uvicorn 走 TCP，断言首末事件时间差。改后到达时刻变为 `[0.002, 0.062, 0.123, 0.182]`。已补进 PRD 12.2。

### 反证：「先查后扣」真的会超卖

故意用错误写法实现后，20 个并发**全部成功**（应为 10），额度被扣穿一倍。换成单条 `INSERT ... ON CONFLICT ... WHERE ... RETURNING` 后恰好 10 个成功。

这条反证的价值：证明超卖测试**确实能抓住 bug**，而不是一个永远通过的摆设。PRD 5.6.2 的原子写法与 CLAUDE.md 红线第 4 条由此得到实证支撑。
